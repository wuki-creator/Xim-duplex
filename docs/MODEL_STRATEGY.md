# Xim 自主产品技术路线

更新：2026-11-16 · v0.9.0。产品采用自己实现的交互编排、状态管理和执行协议。MOSS 仅保留为公开研究参考，当前代码不调用其 API、不加载其模型、不从其权重微调，也不把改名当作自主研发。

## 已实现与边界

| 模块 | 当前实现 | 下一步研发 |
| --- | --- | --- |
| Xim Listen | 持续 PCM 输入、浏览器回声消除请求、独立能量 VAD、服务器 Whisper | 流式增量识别、语义断句、回声和背景说话人过滤 |
| Xim Turn | 已播前缀、父节点、取消标记、旧回调失效；新话按最新意思续接 | 学习 listen / backchannel / yield / reply 的时序策略 |
| Xim Affect | 六种情绪文字色、Three.js 表情、系统朗读韵律参数 | 授权表达数据训练；以温暖、恰当、尊重边界评价，避免一味讨好 |
| Xim Task | DeepSeek 生成受约束结构化指令；运行前检查工具参数和状态 | 自部署小模型处理常见指令，复杂问题再路由 DeepSeek |
| Xim Room | 随机具名 Agent、派工、澄清、版本化方案、确认后执行、结果框；最多两项并行 | 多 Agent 发言调度、任务依赖图、统一会话记忆 |
| Xim World | Three.js / Cannon 场景、固定服务器计算、末端轨迹障碍检查、Blender 导出 | 更完整仿真与连杆碰撞；当前不控制真实机械臂 |

这些是本项目模块名，**不是六个已经训练好的基础模型**。当前声音为设备朗读；本地语音、图像和文本服务有可替换接口，不能把接口通过测试写成模型部署完成。

## 自有技术应该积累在哪里

1. 打断策略：联合音频状态、增量文字、当前播放位置判断让话、附和和继续。训练标签来自已授权互动；被打断后只保留双方共享内容。
2. 对话与行动衔接：保留任务版本和确认状态。用户纠正目标时撤销旧方案的执行资格，不能把取消后的旧结果提交到新任务。
3. 角色表达：文字、声音、表情使用同一组表达事件及播放时间；角色声音采用明确授权素材，评估语义与情绪是否一致。
4. 反馈闭环：每次策略或权重更新有父版本、数据来源、留出集、对照实验和回滚。用户的开心程度不能由模型自己打分证明。

## 模型与数据选择

保留已经部署的 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)（MIT 代码）和原有 Whisper 模型归属。独立声音模型候选包括 [CosyVoice](https://github.com/QwenAudio/CosyVoice)；其代码和 [CosyVoice2-0.5B 模型卡](https://huggingface.co/FunAudioLLM/CosyVoice2-0.5B)标注 Apache 2.0，候选尚未下载或部署。采用开源基础模型时保留准确模型名、修订和许可；业务适配与基础模型分开命名。

继续使用公开 [AISHELL-3](https://www.openslr.org/93) 的数据准备流程；该资源标注 Apache 2.0，属于中性语音，不能训练出有证据支持的开心、安慰或自然插话能力。当前仅有 30 条开发样本。后续完整语音数据、互动轮次标注及产品角色声音是不同数据资产，分别记录来源与用途。

## 递归改进

现有 `evolution/evolve.mjs` 只改提示策略：10 条授权负反馈生成候选；至少 50 条不同的真人 holdout 案例、有评审人、无回归、95% Wilson 胜率下界大于 0.5、P95 回复延迟不超过 4 秒、P95 停播不超过 500 ms，才能晋级。以上是设定门槛，不是已达到的指标。

模型训练计划见 [training/README.md](../training/README.md)。先建立稳定基线和真实对话集，再分别训练轮次判断、结构化任务与情绪表达；不能将语音模型、语言模型权重简单拼接后宣称全双工。

## 商业验证

同一设备和网络下比较“当前独立级联”与每一项新增模块。覆盖安静、外放、噪声、附和、纠正、长停顿、取消任务与弱网；记录首音延迟、停播延迟、误抢话率、纠正理解率、任务成功率、真人偏好和每分钟成本。

当前还没有原生全双工训练结果、真人盲评或领先竞品的证据。创业价值来自可验证的体验、可控的部署成本和持续积累的数据与算法。
