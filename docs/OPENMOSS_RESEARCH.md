# Xim 语音系统：OpenMOSS 公开资料的研发参考

更新：2026-11-16。用户要求参考 OpenMOSS，并开发创业产品。当前版本没有复制 OpenMOSS 源码或加载 MOSS 权重；自有模块采用 Xim 名称。使用上游代码或衍生权重时应保留其来源、许可证、版本以及修改说明，不能仅改名来声称从零自研。

## 可以借鉴的技术组织

| 上游公开参考 | Xim 研发方向 | 当前状态 |
| --- | --- | --- |
| [MOSS-Live](https://github.com/OpenMOSS/MOSS-Live) 的前台实时交互和后台推理分工 | 前台常驻监听、处理用户接话；后台执行会议与工作台任务 | 已拆分会话和任务入口，音频仍是整句识别；后台与主对话共用一个文本服务、单 GPU 锁，尚无隔离调度 |
| [MOSS-TTS-Realtime 微调文档](https://github.com/OpenMOSS/MOSS-TTS/blob/main/moss_tts_realtime/finetuning/README.md) 的音频编码预处理、训练和评测分离 | 语音数据治理、音频 token、训练与部署分阶段版本化 | 只有公开 AISHELL-3 小样本格式检查；没有 token 提取、训练或音色权重 |
| [MOSS-TTS](https://github.com/OpenMOSS/MOSS-TTS) 的流式语音设计 | 文字按边界增量送入语音合成，按音频块回报已播放位置并可撤销后续块 | 当前仅在完整文字回复后分段播放，语音为系统朗读；尚非流式神经 TTS |

MOSS-Live 公开仓库介绍架构和评测并提供在线服务入口，不应假设完整可训练权重已经公开。其报出的实验结果属于上游，不能套用到 Xim。

## Xim 前台 / 后台边界

前台：连续音频、VAD、可中断播放、按已播放前缀续接；后台：任务方案、明确确认、受约束执行、独立结果。需要补上更稳健的回声处理、增量 ASR、语义轮次、流式输出、后台排队与取消传播，才能验证自然对话。当前单模型和简单 VAD 不能实现上游所展示的完整行为。

## 训练与可验证性

AISHELL-3 的公开样本是中性朗读数据，不能直接监督双人重叠对话、打断或情绪表达。下一步应分别构建经过授权的互动轮次数据与声音训练数据，按说话人和会话隔离训练 / 测试，记录基座、数据、训练脚本和 checkpoint 的版本及授权。模型更名为 Xim 的产品名不会使第三方权重变成从零训练。

依次评估转写错误率、用户开口到停播、轮次结束到首音、附和误抢话率、被纠正后理解率、真实用户偏好与成本。没有实际训练、硬件测量和独立真人评估之前，不声称自进化或达到竞品水平。
